# PRD：Build 儿童积木创作工作室（MVP）

> 状态：MVP 纵向切片已实现 0.2  
> 日期：2026-08-03  
> 本轮范围：已实现核心纵向链路；语音、可配置库存、作品版本/改造与完整搭建求助留待后续

## 1. 产品概述

将登录后的默认工作区入口从 `/{workspaceSlug}/issues` 改为
`/{workspaceSlug}/build`，并新增面向 6–12 岁儿童的积木创作工作室。

儿童先用一句话描述想法，例如“我想做一只会保护宝藏的机械小狗”。AI
最多追问 3 个真正影响结构的问题，然后在已知积木库存范围内生成一份经过校验、
可以真实搭建的方案。方案包含积木形象、零件清单和逐步搭建指引，并自动保存到
“我的作品”。

家长拥有并登录账号。儿童模式只显示“开始创作”和“我的作品”；Issues、Agents、
Settings 等管理能力只在经过家长验证后出现。

### 1.1 已确认的产品决策

- 产物必须是可真实搭建的方案，而不只是积木风图片。
- 创作从一句话开始，AI 可通过对话追问。
- 账号由家长持有，主要使用者是 6–12 岁儿童。
- 儿童只看到 Build 和作品库，原有管理功能进入家长模式。
- 首要成功标准是儿童在 60 秒内得到并保存第一个满意方案。

### 1.2 关键定义

- **Build / 开始创作**：提出想法并生成新方案的页面。
- **作品**：一个持续演化的发明项目，例如“守护宝藏的机械小狗”。
- **版本**：同一作品的一次可搭建方案；“改一改”会生成新版本，不覆盖旧版本。
- **搭建方案**：结构化积木模型、库存快照、零件清单、搭建步骤和校验结果的集合。
- **可搭建**：方案只使用库存中存在的零件和数量；所有零件均有合法连接，不发生
  空间碰撞，并通过 MVP 定义的基础支撑与稳定性检查。它不等于工程安全认证。
- **儿童模式**：默认的受限产品外壳，只显示创作相关能力。
- **家长模式**：通过家长验证后短时解锁的管理外壳。

## 2. 产品原则

1. **孩子是发明家，AI 是引导者。** AI 帮助理解、规划和排错，不替孩子完成实体搭建。
2. **先保证能搭，再追求像照片一样好看。** 预览必须来自结构化模型的确定性渲染，
   不能用一张无法复现的生成图片冒充搭建方案。
3. **少读、少写、多选择。** 追问优先使用带图选项和语音，最多 3 轮，并始终提供
   “你帮我选”和“我不知道”。
4. **每次只给一个下一步。** 搭建模式聚焦当前零件和当前动作，避免把完整说明书一次
   塞给儿童。
5. **失败也能继续创造。** 找不到零件、装不上、结构倒塌时，应给替代结构，而不是只
   显示错误。
6. **儿童安全与隐私是默认能力。** 不依赖儿童理解复杂设置，也不通过公开社区、广告或
   排行榜推动使用。

## 3. 目标

- 登录或切换工作区后，默认进入 `/{workspaceSlug}/build`。
- 儿童提交第一句话后，AI 最多用 3 个问题收集完成方案所需的信息。
- 系统只向儿童展示通过库存、连接、碰撞和基础稳定性校验的方案。
- 每份方案都包含可旋转的整体预览、准确零件清单和可顺序执行的搭建步骤。
- 方案生成成功后自动保存，儿童不需要理解文件、项目或保存按钮。
- 儿童可以在搭建中表达“没有这块”“装不上”“想改造”，并得到仍然可校验的替代方案。
- 儿童模式不暴露 Issues、Agents、成员、运行时、费用或系统设置。
- Web 与 Desktop 使用同一业务页面和相同产品语义。

## 4. 信息架构

### 4.1 儿童模式

| 路由 | 页面 | 主要任务 |
| --- | --- | --- |
| `/{slug}/build` | 开始创作 | 输入想法、回答追问、等待生成 |
| `/{slug}/creations` | 我的作品 | 继续搭建、查看和再次改造 |
| `/{slug}/creations/{id}` | 作品详情 | 查看方案、分步搭建、请求帮助 |

儿童模式导航只出现：

- 开始创作
- 我的作品
- 右上角家长入口（锁形图标 + “家长”）

### 4.2 家长模式

家长验证成功后，显示现有管理导航，以及新增的：

- 儿童模式设置：昵称、年龄段、语音开关和隐私设置
- 我的积木箱：选择可用套装和零件数量
- 使用概览：只展示作品数、搭建进度和使用时长，不展示儿童排名

家长模式退出、超时或应用重启后，自动回到儿童模式。直接访问原有管理路由时，
如果没有有效的家长模式授权，必须显示家长验证，不能只依赖侧栏隐藏。

### 4.3 默认入口变更

以下入口统一改为 Build；已有深链接仍保持原目标：

- 登录完成后的默认目的地
- 已登录用户从产品首页进入应用
- 访问裸工作区路由 `/{slug}`
- Web 根路由根据最近工作区跳转
- 工作区切换器的默认目标
- Desktop 新工作区标签页的种子页面
- Desktop 关闭最后一个标签页后的恢复页面
- Desktop 路由错误后的安全恢复页面

邀请链接、指定 `next` 链接、作品详情和 Issue 详情深链接不得被 Build 覆盖。

## 5. 核心用户流程

### 5.1 家长首次设置（不计入儿童 60 秒指标）

1. 家长登录并完成工作区创建。
2. 选择儿童年龄段：6–8 岁或 9–12 岁；不收集完整生日。
3. 选择一个受支持的积木套装，或使用默认的 CHIMII Starter Kit。
4. 设置家长模式 PIN；忘记 PIN 时必须通过完整账号验证重置。
5. 点击“交给孩子”，进入儿童模式的 Build 页面。

### 5.2 一句话开始创作

1. 页面用大号输入区询问：“今天想造什么？”
2. 儿童可以输入文字，或按住麦克风说一句话。
3. 页面给出 3–4 个可点选的灵感例子，但不会自动提交。
4. 输入通过安全检查后进入追问；原始音频完成转写后立即删除。

### 5.3 AI 追问

AI 只能追问影响可搭建性的高价值信息，最多 3 个问题：

- 尺寸：手掌大小、书本大小，或“你帮我选”
- 核心特征：会摇尾巴、能张嘴、可以推着走
- 风格或颜色：勇敢、可爱、古怪，或从库存可用颜色中选择

每个问题优先显示 2–4 个带图答案。儿童可输入自己的答案，也可随时选择
“直接帮我设计”。如果已有信息足够，系统应少问或不问。

### 5.4 方案生成

生成状态使用儿童能理解的三个阶段：

1. “我在理解你的想法”
2. “我在积木箱里找零件”
3. “我在检查它能不能搭起来”

系统先生成结构化模型，再执行确定性校验和渲染。校验失败时在后台自动修复，
不能把未校验结构显示给儿童。

### 5.5 方案结果

结果页首屏只强调三件事：

- 可旋转的积木形象与作品名称
- “开始搭建”主按钮
- “改一改”次按钮

零件数量、预计难度、预计搭建时间和尺寸作为简短标签显示。“用了哪些积木”可以展开，
不在首屏制造压力。方案生成成功即自动保存到“我的作品”，并明确显示“已经帮你保存”。

### 5.6 分步搭建

- 每屏只展示一个步骤。
- 当前步骤高亮本步新增零件，已完成结构降低对比度。
- 明确展示零件外形、颜色、数量和连接位置。
- 支持旋转、缩放、上一步、下一步和“看不懂”。
- 点击“看不懂”后，可选择“找不到这块”“不知道装哪里”“装不上”“它倒了”。
- 系统优先解释；需要替换结构时生成新版本并重新校验。
- 完成最后一步后，儿童可以给作品命名、选择表情贴纸并标记“完成了”。

## 6. 页面与状态设计

### 6.1 Build 首页

**空闲态**

- 中心为一句话输入区，而不是聊天记录或成人工作台。
- 文案简短：“说说你想造什么，剩下的我们一起想。”
- 显示最近 3 个作品的“继续搭建”，避免儿童从作品库寻找。

**输入态**

- 实时显示字符或语音转写，但不显示成人化 token、模型或额度信息。
- 提交按钮使用动作语言“开始想办法”。
- 空输入、过长输入和网络离线使用可恢复提示。

**追问态**

- 每次只显示一个问题。
- 显示最多 3 格的轻量进度，但不承诺一定问满 3 个。
- 选项必须可触控，最小点击区域 44×44 CSS 像素。

**生成态**

- 显示具体进度阶段和取消按钮。
- 离开页面不取消任务；回来后可恢复进度。
- 超过 60 秒显示“还在检查结构”，同时允许稍后在作品库查看。

**安全改写态**

- 不使用惩罚性或成人化错误文案。
- 示例：“这个想法可能会伤到人。我们可以把它改成会发射彩色纸旗的守护机器人。”
- 提供 2–3 个安全替代方向和“换一个想法”。

**失败态**

- 保留已经输入和回答的内容。
- 提供“再试一次”和“让它简单一点”。
- 技术错误、库存不足和无法形成稳定结构必须有不同的恢复动作。

### 6.2 我的作品

- 默认按最近继续搭建排序。
- 卡片显示模型预览、名称、状态（设计好了／搭建中／完成了）和最后活动时间。
- 不显示点赞数、排名、连续打卡或公开曝光量。
- 删除作品属于家长操作；儿童可以“收起来”，进入归档。

### 6.3 视觉与交互方向

- 延续当前品牌已有的“发明工作台”视觉：暖色纸张、蓝图、粗线条机械插画和实体质感。
- 视觉应像儿童工作室，不像聊天机器人、项目管理器或电商商品页。
- 颜色用于表达情绪和层级，但状态不能只依赖颜色。
- 中文优先使用儿童能直接理解的动词：“开始搭建”“换一块”“再试试”。
- 6–8 岁模式减少文字并默认开启朗读；9–12 岁模式可显示更多结构解释。
- 支持键盘操作、减少动态效果、清晰焦点和读屏标签。

### US-008：最多三轮智能追问

### US-009：儿童安全检查与安全改写

**描述：** 作为家长，我希望输入和输出均经过儿童安全检查，以便创作不会引向危险内容。

**验收标准：**

- [ ] 每次原始想法、补充回答、生成方案和改造请求都经过安全策略。
- [ ] 禁止真实武器、危险投射物、火焰、高温、市电、尖锐结构、成人内容、自伤、仇恨和索取个人信息。
- [ ] 被阻止时返回适龄解释和至少两个安全替代方向。
- [ ] 预览、零件列表和步骤必须属于同一已校验结构版本。
- [ ] 安全审计日志不存储原始儿童音频；查看原始文本需要严格受控。
- [ ] 后端策略和回归样例测试通过。

### US-010：生成结构化搭建方案

**描述：** 作为儿童，我希望 AI 给出真实模型而不是一张假想图片，以便可以照着搭建。

**验收标准：**

- [ ] 生成结果符合版本化的搭建方案 JSON Schema。
- [ ] 每个零件实例包含目录 ID、颜色、空间变换和连接关系。
- [ ] 每个实例都被且只被一个搭建步骤引入。
- [ ] 零件总量不超过生成开始时记录的库存快照。
- [ ] 模型输出失败或超时不会创建“可搭建”状态。
- [ ] API 响应通过 Zod schema 和 `parseWithFallback` 解析，并覆盖畸形响应测试。

### US-011：确定性校验和自动修复

**描述：** 作为家长，我希望系统验证方案结构，以便“可搭建”不是未经检查的 AI 声明。

**验收标准：**

- [ ] 校验器检查库存数量、合法连接、空间碰撞、悬空零件和基础支撑。
- [ ] 校验结果包含机器可读错误码和定位到零件实例的错误信息。
- [ ] 初次失败最多自动修复两次，每次都重新执行完整校验。
- [ ] 未通过校验的版本不得进入儿童结果页或作品库可搭建状态。
- [ ] 固定套装的至少 50 个基准创意通过离线回归测试。
- [ ] Go tests pass。

### US-012：渲染预览、清单和搭建步骤

**描述：** 作为儿童，我希望从不同角度看模型并逐步搭建，以便知道每块积木放在哪里。

**验收标准：**

- [ ] 预览由结构化模型确定性渲染，不调用自由图像生成替代模型。
- [ ] 整体预览支持旋转、缩放和重置视角。
- [ ] 零件清单与模型实例按零件 ID、颜色和数量完全一致。
- [ ] 每步只高亮新加入零件，并提供推荐相机视角。
- [ ] 上一步、下一步和刷新后恢复当前步骤均可用。
- [ ] Typecheck/lint passes。
- [ ] Verify in browser using dev-browser skill。

### US-013：搭建困难与结构替代

**描述：** 作为儿童，我希望在没有零件或装不上时获得具体帮助，以便继续完成作品。

**验收标准：**

- [ ] “看不懂”菜单包含找不到零件、不知道位置、装不上和结构不稳。
- [ ] 解释可以放大并高亮相关连接点。
- [ ] 需要更换零件时，系统生成新版本且保留旧版本。
- [ ] 新版本只能使用剩余库存，并重新执行全部校验。
- [ ] 儿童可以回到旧版本，版本切换不会覆盖搭建进度。
- [ ] Typecheck/lint passes。
- [ ] Verify in browser using dev-browser skill。

### US-014：自动保存和我的作品

**描述：** 作为儿童，我希望作品自动保存并能继续搭建，以免因为不会管理文件而丢失创作。

**验收标准：**

- [ ] 首个校验通过的版本生成后自动创建作品并显示保存成功。
- [ ] 作品记录设计好了、搭建中和完成了三种儿童可见状态。
- [ ] 作品库按最近活动排序，并提供最近作品的继续入口。
- [ ] 归档可由儿童执行，永久删除必须进入家长模式确认。
- [ ] 每个作品保存当前版本、当前步骤和最近活动时间。
- [ ] Typecheck/lint passes。
- [ ] Verify in browser using dev-browser skill。

### US-015：隐私安全的成功指标

**描述：** 作为产品团队，我希望衡量儿童是否快速完成第一份作品，同时不把儿童创作内容发送到分析系统。

**验收标准：**

- [ ] 记录想法提交、追问完成、方案校验通过、自动保存、开始搭建、求助和完成事件。
- [ ] 分析事件只包含内部 ID、年龄段、套装 ID、耗时和结果码。
- [ ] 分析事件不得包含原始想法、对话文本、作品名、音频、图片或个人信息。
- [ ] 可以计算从首次提交到首个自动保存方案的完整耗时。
- [ ] 可以按 Web/Desktop、年龄段和套装查看聚合漏斗。
- [ ] 分析事件 schema 测试通过。

## 8. 功能需求

### 8.1 路由与模式

- **FR-1：** 系统必须提供工作区级 `/{slug}/build`、`/{slug}/creations` 和
  `/{slug}/creations/{id}` 路由。
- **FR-2：** 正常登录、工作区切换、裸工作区访问和安全恢复必须默认进入 Build。
- **FR-3：** 明确深链接、邀请和 onboarding 必须保留原有优先级。
- **FR-4：** 儿童模式必须是家长设置完成后的默认模式。
- **FR-5：** 管理路由必须验证短期家长授权，不能只依赖客户端导航隐藏。
- **FR-6：** 家长授权必须支持主动锁定、自动超时、失败限速和账号验证重置。

### 8.2 创作输入与追问

- **FR-7：** 系统必须允许儿童使用文字或按住说话提交一个创意。
- **FR-8：** 原始音频必须在转写完成或失败后删除。
- **FR-9：** 输入和每次回答必须在进入生成模型前执行儿童安全检查。
- **FR-10：** AI 最多提出 3 个问题，每次只问一个。
- **FR-11：** 每个问题必须允许选择“你帮我选”，避免流程阻塞。
- **FR-12：** 追问不得索取任何用于识别或联系儿童的信息。

### 8.3 库存与生成

- **FR-13：** 生成必须基于版本化零件目录和不可变库存快照。
- **FR-14：** MVP 只能使用明确受支持的固定套装；未知散件不得计入可用库存。
- **FR-15：** 结构化方案必须包含零件实例、颜色、空间变换、连接关系和搭建步骤。
- **FR-16：** 生成服务必须校验 JSON Schema，拒绝缺字段或未知版本。
- **FR-17：** 校验器必须检查数量、连接合法性、碰撞、悬空和基础支撑。
- **FR-18：** 校验失败可自动修复两次；仍失败则进入可恢复失败状态。
- **FR-19：** 未通过完整校验的版本不得标记为可搭建。
- **FR-20：** 生成任务必须可异步恢复，页面离开或刷新不能丢失任务。

### 8.4 方案呈现与搭建

- **FR-21：** 模型预览必须从最终结构化版本渲染。
- **FR-22：** 零件清单数量必须与模型实例完全一致。
- **FR-23：** 每个模型实例必须出现在恰好一个搭建步骤中。
- **FR-24：** 每一步必须包含当前新增零件、连接目标和推荐视角。
- **FR-25：** 系统必须保存儿童当前搭建步骤。
- **FR-26：** 帮助入口必须区分缺零件、位置不明、连接失败和不稳定。
- **FR-27：** 任何结构替代必须创建新版本、重新校验并保留历史版本。

### 8.5 作品与数据

- **FR-28：** 首个通过校验的方案必须自动保存为作品。
- **FR-29：** 作品必须支持设计好了、搭建中、完成了和归档状态。
- **FR-30：** 儿童可以归档，只有家长可以永久删除。
- **FR-31：** 家长可以删除某个作品及其版本、预览、转写文本和关联分析映射。
- **FR-32：** 产品分析不得包含原始儿童内容或可识别信息。

### 8.6 安全

- **FR-33：** 系统必须阻止成人内容、自伤、仇恨、真实武器和危险机械结构。
- **FR-34：** MVP 方案不得使用市电、火焰、高温、锋利物、弹射物或需工具切割的步骤。
- **FR-35：** 被阻止的想法必须提供适龄、安全且仍保留原想象主题的替代方向。
- **FR-36：** 产品不得提供公开作品流、儿童私信、广告、点赞排名或陌生人互动。

## 10. 技术考虑

### 10.1 前端边界

- 共享业务页面放入 `packages/views/build/`，供 Web 和 Desktop 复用。
- API 类型、React Query hooks、生成任务状态和纯校验辅助逻辑放入 `packages/core/build/`。
- 服务器状态由 React Query 管理；输入草稿、当前步骤等客户端视图状态才进入 Zustand。
- `packages/views` 通过 `NavigationAdapter` 跳转，不直接依赖 Next.js 或 React Router。
- Web 在 `apps/web/app/[workspaceSlug]/(dashboard)/build/` 接线；Desktop 在路由表接线。
- 语音录制属于平台能力，通过适配器注入共享视图，避免共享包直接依赖浏览器或 Electron API。

### 10.2 后端生成流水线

```text
儿童想法
  → 输入安全检查
  → 追问决策
  → 结构化方案生成
  → JSON Schema 校验
  → 库存校验
  → 连接与碰撞校验
  → 基础稳定性校验
  → 失败时自动修复（最多 2 次）
  → 确定性渲染预览和步骤
  → 自动保存作品版本
```

- 生成应使用异步任务；客户端通过实时事件或轮询恢复状态。
- 每个阶段使用稳定错误码，儿童文案由前端根据错误码本地化。
- 生成模型不得直接决定“校验通过”；最终状态只能由确定性校验器写入。
- 模型、零件目录、校验器和提示模板都必须记录版本，保证历史作品可重现。

### 10.3 数据存储建议

- `child_profiles`：工作区、昵称、年龄段和儿童模式偏好。
- `brick_inventories`：零件目录版本与数量。
- `build_projects`：作品身份、状态、当前版本和当前步骤。
- `build_revisions`：输入摘要、结构化方案、库存快照、校验结果和生成状态。
- `build_generation_jobs`：异步阶段、错误码、重试次数和耗时。

按仓库约束，表之间不添加数据库外键；关系校验和级联清理由应用层事务完成。
所有索引使用独立迁移文件中的 `CREATE [UNIQUE] INDEX CONCURRENTLY`。

### 10.4 API 与兼容性

- 所有 UI 消费的响应均定义 Zod schema，并使用 `parseWithFallback`。
- 枚举 switch 必须有默认分支，旧 Desktop 客户端遇到新状态时降级为“处理中”或“需要重试”。
- 生成任务接口应幂等，重复提交同一客户端请求 ID 不得创建多个扣费任务。
- 作品删除必须等待服务端成功后再从缓存和页面移除。
- 方案版本保存后不可原地修改；修复和改造都创建新版本。

### 10.5 性能预算

- 追问接口首屏反馈 P95 小于 1.5 秒。
- 选择答案后下一个问题 P95 小于 1 秒。
- 最终回答提交后，P50 在 20 秒内得到校验方案，P95 在 60 秒内。
- 从第一次提交想法到首个方案自动保存，至少 80% 的成功会话不超过 60 秒。
- 3D 首屏可交互时间 P75 小于 2.5 秒；先显示低清预览，再加载完整几何数据。

## 11. 安全与隐私

- 不收集完整出生日期、学校、地址、联系方式或生物特征。
- 语音只用于当前转写，原始音频不落长期存储。
- 默认不使用儿童输入、音频、模型或作品训练通用模型。
- 产品分析只发送分类和耗时，不发送原文或作品内容。
- 家长可以查看、导出和删除家庭数据。
- 不做公开分享、评论、关注、私信、广告或基于参与度的推荐。
- 涉及受版权保护角色的请求应引导为儿童自己的原创角色，不承诺复刻商业 IP。
- 产品必须明确提示“小零件需要家长根据实际情况监督”，但不能用免责声明替代结构安全策略。

## 12. 非目标

- MVP 不识别家中任意散装积木照片，也不保证支持未知零件。
- MVP 不以自由图像生成作为方案来源。
- MVP 不生成电机、电路、市电、弹射、切割或加热相关方案。
- MVP 不提供公开作品社区、社交关系、陌生人互动或排行榜。
- MVP 不支持儿童独立账号或绕过家长的登录方式。
- MVP 不支持手机端完整创作与 3D 搭建流程。
- MVP 不提供积木购买、缺件电商链接或商业品牌套装市场。
- MVP 不删除现有 Issues 等管理能力，只将其移入家长模式。
- “可搭建”不构成玩具认证、承重认证或工程安全保证。

## 13. 成功指标

### 13.1 北极星指标

**首次有效创作率：** 首次提交想法的儿童会话中，在 60 秒内获得并自动保存一份
校验通过方案的比例，MVP 目标不低于 80%。

计时从儿童第一次提交完整想法开始，到服务端确认首个通过校验的版本已保存为止；
追问时间包含在内，家长首次库存设置不包含在内。

### 13.2 质量指标

- 95% 以上生成任务在初次生成或两次自动修复内通过确定性校验。
- 100% 展示为“可以搭”的方案都有完整校验记录。
- 零件清单与模型实例数量一致率为 100%。
- 50 个固定套装基准创意的自动回归通过率为 100%。

### 13.3 行为指标

- 获得方案的儿童中，至少 60% 点击“开始搭建”。
- 开始搭建的作品中，至少 30% 被标记为完成。
- 发起“看不懂”的会话中，至少 70% 在帮助后继续下一步。
- 首次创作中位追问数不超过 2，放弃率低于 15%。

### 13.4 安全指标

- 输入、回答、改造和输出的策略检查覆盖率为 100%。
- 分析事件中原始儿童文本、音频或图片泄漏为 0。
- 未获家长授权访问管理路由的成功率为 0。

## 14. 风险与缓解

| 风险 | 影响 | 缓解方案 |
| --- | --- | --- |
| “可搭建”承诺过强 | 儿童按图无法完成，迅速失去信任 | MVP 限定固定套装；结构化生成；确定性校验；先做离线基准测试 |
| 追问拖慢 60 秒目标 | 儿童中途离开 | 最多 3 问；优先图形选项；始终允许“你帮我选”；信息足够就跳过 |
| 好看的图与真实结构不一致 | 视觉惊喜变成产品欺骗 | 预览只从最终结构化模型渲染，不使用独立图像生成 |
| 儿童进入管理功能 | 误操作成员、费用或运行时 | 服务端短期家长授权；直接路由守卫；重启自动锁定 |
| 结构校验耗时 | 超过首创 60 秒 | 固定目录、缓存几何、分阶段反馈、生成与校验并行优化 |
| 任意家庭库存难以识别 | 生成缺件或错件方案 | MVP 只支持预设套装，照片盘点推迟到后续验证 |
| 儿童内容进入分析或训练 | 隐私与合规风险 | 原始内容与分析隔离；音频即时删除；默认禁止训练用途 |

## 15. 建议实施阶段

### 阶段 0：可搭建性风险验证

- 选定一个固定积木套装并建立版本化零件目录。
- 完成结构 JSON Schema、连接规则和基础碰撞校验原型。
- 用 50 个覆盖宠物、车辆、建筑和机关外观的儿童想法跑离线生成。
- 达到 95% 自动修复后可通过校验，否则不进入完整 UI 开发。

### 阶段 1：路由与儿童外壳

- 新增 Build 和作品库路由。
- 统一 Web/Desktop 默认入口。
- 完成儿童模式、家长验证和积木箱设置。

### 阶段 2：创作闭环

- 一句话输入、安全策略和最多三轮追问。
- 异步结构生成、校验、修复、渲染和自动保存。
- 完成结果页和失败恢复状态。

### 阶段 3：实体搭建闭环

- 分步搭建、当前步骤恢复和困难帮助。
- 结构替代与作品版本历史。
- 作品完成与家长数据管理。

### 阶段 4：质量门槛

- 60 秒性能优化、基准创意回归和安全红队测试。
- Web/Desktop 浏览器与实机视觉验证。
- 小范围家庭测试后再扩大支持的套装。

## 16. 待确认问题

1. **MVP 的固定库存是什么？** 建议先定义一个 CHIMII Starter Kit，或明确选择一个
   现有通用套装；这是开始实现前唯一真正阻塞生成引擎的问题。
2. **首版是否支持多个儿童档案？** 建议 MVP 每个工作区只启用一个儿童档案，但数据模型
   保留多档案能力，避免首创前出现“选谁在使用”的额外步骤。
3. **家长验证形式是什么？** 建议首次设置 4 位 PIN，重置必须重新验证账号；解锁有效
   15 分钟，可随时主动锁定。
4. **语音是否进入 MVP？** 面向 6–8 岁时建议进入 MVP；如果需要缩短研发周期，可先上线
   文字输入，但产品验证样本应以 9–12 岁为主。
5. **整体模型的首版呈现形式是什么？** 建议结果页使用可旋转 3D，搭建步骤同时生成稳定
   视角的 2D 缩略图，兼顾理解与低性能设备。
